# Karina — Telethon-бот, отвечает только новым контактам

Личный аккаунт +79805247203 (Telethon, не Bot API). Ключевое правило:
**бот никогда не пишет и не отвечает тем, с кем в этом аккаунте уже была
переписка** — ни истории от других проектов (Roman, lead_magnit и т.д.),
ни личным контактам владельца. Отвечает только тем, кто пишет впервые.

## Как это работает

1. Входящее сообщение от юзера, с которым ещё нет записи в локальной БД →
   [`tg/gatekeeper.py`](tg/gatekeeper.py) проверяет историю ЭТОГО чата в
   самом Telegram (`get_messages(..., offset_id=<id входящего>)`).
   - Если до этого сообщения в чате уже что-то было (в любую сторону) —
     чат помечается `existing`, бот молчит в нём навсегда.
   - Если ничего не было — это подлинно первый контакт, чат помечается
     `new`, и дальше бот ведёт его.
2. Проверка идёт один раз на чат и кэшируется в SQLite (`data/karina.db`) —
   переживает рестарты бота (в отличие от снимка диалогов при старте,
   который бы ошибочно «состарил» чаты, отвеченные ботом до перезапуска).
3. Сообщения от `new`-юзера копятся в батче ~7 сек
   ([`tg/message_batcher.py`](tg/message_batcher.py) — код из проекта
   Roman), затем вся история переписки (не только последний батч) целиком
   уходит в Poe, чтобы модель помнила весь диалог.
4. Если владелец аккаунта сам вручную пишет в чат, который ведёт бот, —
   чат немедленно и НАВСЕГДА помечается `existing`: бот больше никогда не
   ответит в этом чате (без тайм-аутов и пауз — тот же необратимый статус,
   что и у чатов с историей до бота).

## Архитектура ботов Poe (как в Roman — два вынесенных бота)

**В коде нет ни промпта, ни персоны, ни бизнес-логики.** [`tg/worker.py`](tg/worker.py)
только собирает сопутствующие данные и пересылает их двум ботам,
настроенным на poe.com:

1. **`POE_CLASSIFIER_MODEL`** (опционально) получает историю диалога +
   данные компании/менеджера, возвращает произвольный текст (классификацию/
   разметку) — код не разбирает и не интерпретирует этот вывод, просто
   передаёт его дальше.
2. **`POE_CHAT_MODEL`** получает ту же историю + вывод классификатора
   (если он был) и возвращает готовый текст ответа — он и уходит клиенту.

Персона, стиль ответов, сценарий разговора и то, что вообще делает
классификатор, — всё это настраивается на стороне Poe при создании ботов,
а не в этом репозитории. Если `POE_CLASSIFIER_MODEL` пуст — этот шаг просто
пропускается, работает один `POE_CHAT_MODEL`.

## Каталог (данные компании «Алико потолки»)

[`knowledge/catalog.json`](knowledge/catalog.json) — прайс-лист (6 типов
потолков, цена материала и цена под ключ за м², бренды, гарантия, промо),
спарсен с https://aliko-potolki.ru/ и согласован с заказчиком.
[`services/catalog.py`](services/catalog.py) читает файл один раз при
старте, [`tg/worker.py`](tg/worker.py) добавляет его как есть (сырой JSON,
без парсинга) в каждый запрос к обоим ботам Poe — это тоже просто
«сопутствующие данные», не логика.

⚠️ В каталоге есть поле `install_price_conflict` у матовых потолков — на
сайте самого заказчика указаны две разные цены под ключ (390 и 1300 руб/м²)
на разных страницах. Расхождение не исправлено, только помечено.

## Промпты ботов (poe_bots/)

[`poe_bots/`](poe_bots) — референс-копии системных промптов, вставленных
в конструктор ботов на poe.com. Код их не читает и не отправляет — только
для версионирования, чтобы промпт на Poe и копия в репозитории не
разъезжались со временем.

- [`poe_bots/maksim_dialog.md`](poe_bots/maksim_dialog.md) — диалоговый
  бот «Максим», уже создан на Poe как `Aliko_Dialog`. Получает от кода
  историю диалога + сообщения [ДАННЫЕ]/[КАТАЛОГ JSON]/[КЛАССИФИКАЦИЯ]
  (см. `tg/worker.py`).
- [`poe_bots/aliko_classifier.md`](poe_bots/aliko_classifier.md) —
  классификатор под intent-набор Максима (`answer/greeting/price_inquiry/
  service_inquiry/catalog_search/consultation/order/complaint/unclear`),
  создан на Poe как `aliko_classfilter`. Старый классификатор Романа
  (`answer/unclear_answer/question/multi/go_back/invalid_answer/
  off_topic/greeting`) не подходил, intent-наборы не пересекались.

## Настройка

Секреты для +79805247203 уже прописаны в `.env` (взяты из `Roman/.env`,
API_ID/HASH те же — сессия при этом отдельная, `data/karina.session`,
Roman и lead_magnit не трогаются).

**Обязательно перед запуском:**

- Диалоговый бот на Poe уже создан — `POE_CHAT_MODEL=Aliko_Dialog`.
- Классификатор тоже создан — `POE_CLASSIFIER_MODEL=aliko_classfilter`,
  промпт из [`poe_bots/aliko_classifier.md`](poe_bots/aliko_classifier.md).

## Тестовый режим (SELF_TEST)

`SELF_TEST=1` в `.env` — весь тест идёт в Избранном (Saved Messages),
реальным юзерам ничего не уходит:

- Пишешь себе в Избранное обычным текстом → бот воспринимает это как
  входящее от «клиента» (гарантированно `new`, даже если раньше уже
  тестировал и чат стал `existing` — см. `db.force_new`).
- Ответ бота приходит туда же, с меткой 🤖 в начале — так видно, где чьи
  реплики в одной переписке с самим собой.
- Правило «не пишем в существующие чаты» на тестовый чат не действует —
  это песочница, а не проверка реального юзера.

После теста верни `SELF_TEST=0` для реальной работы.

## Запуск

```bash
pip install -r requirements.txt
python main.py
```

Первый запуск интерактивный: Telegram пришлёт код подтверждения на
+79805247203 — ввести один раз в консоли, дальше работает
`data/karina.session`.
